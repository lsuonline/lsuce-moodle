# BUG-002 — simple_restore/list.php shows only "Dashboard" in breadcrumbs

**Ticket:** MD-2189  
**Reported:** 2026-05-08  
**Status:** Fixed (same session)  
**Severity:** Low — page functions correctly, cosmetic nav issue  

---

## Screenshot

`/blocks/simple_restore/list.php` renders with only "Dashboard" in the breadcrumb trail. Expected: Dashboard > [Course Name] > Simple Restore.

---

## Root cause

`list.php` lines 132–137 set the page context and course, then add the block name to the navbar:

```php
$PAGE->set_context($context);
$PAGE->set_course($course);
$PAGE->navbar->add($blockname);          // ← only adds "Simple Restore"
$PAGE->set_title($blockname.': '.$heading);
$PAGE->set_heading($blockname.': '.$heading);
$PAGE->set_url($baseurl);
```

`$PAGE->set_course($course)` makes the course available to the page but does **not** automatically inject the course link into the navbar in all themes. The explicit `navbar->add($blockname)` appended only the block name with no parent link, so the breadcrumb trail collapsed to Dashboard → Simple Restore (with "Simple Restore" often invisible in Snap theme).

The same pattern was already applied correctly in the grade-warning early-exit path (line 80) which did add the course link:
```php
$PAGE->navbar->add($course->fullname, new moodle_url('/course/view.php?id='.$course->id));
```

The main page setup path was missing the equivalent course link.

---

## Fix applied

Add the course link to the navbar before adding the block name. Guard against archive mode (system context) and the site course (id=1) where a course link is not appropriate:

```php
// Before:
$PAGE->navbar->add($blockname);

// After:
if (!$archivemode && $course->id != SITEID) {
    $PAGE->navbar->add($course->fullname, new moodle_url('/course/view.php', ['id' => $course->id]));
}
$PAGE->navbar->add($blockname);
```

Breadcrumb trail is now: **Dashboard → [Course Fullname] → Simple Restore**.

---

## Note on the "Filter Courses" / "Enter a valid course shortname" state

The screenshot also shows the admin course filter form with a validation error. This appears when:
- An admin navigates to `list.php?id=<SITEID>` or `list.php?id=<any>` without a `shortname` param
- The form is submitted empty

This is expected behaviour — the filter form is intentional for admins who need to pick a course. Accessing the page with the full params (`?id=2&shortname=TEST-BACKADEL-2026`) bypasses the filter form entirely and goes directly to the backup list.
